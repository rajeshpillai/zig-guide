## Why does `main` take a parameter?

If you have seen Zig before, you probably expect `pub fn main() !void`. That
still compiles:

<Playground
  name="01-getting-started.older-main"
  note="The older shape. Compiled by CI against master every night to prove the claim above, but not executed here."
/>

On current Zig master there is also a form that takes an argument:

```zig
pub fn main(init: std.process.Init) !void
```

`init.io` is an **`Io`**: a value carrying the ability to do input and output.
Writing to a file, opening a socket, reading the clock: each of those takes an
`Io` as an argument, so code cannot block or start a thread unless a caller
handed it one. There is no global `stdout` to reach for. You are handed the
capability to write, and the program above passes it straight through to
`writeStreamingAll`.

Who does the handing is then the caller's choice, which is where the threaded
and event-loop implementations come in. That is
[the `Io` interface](/learn/standard-library/io-interface/), a later chapter;
here it is enough that `main` was given one.

(If you already know Zig's `Allocator`, this is the same move applied to I/O:
the caller supplies the mechanism, and nothing happens behind your back.)

## Buffering, and the `flush` you must not forget

`writeStreamingAll` is fine for a single fixed string, but real programs format
output. For that you want a buffered writer:

<Playground name="01-getting-started.buffered-stdout" />

Since Zig 0.15 (the release nicknamed *"writergate"*), writers are buffered and
the buffer is part of the **interface**, not the implementation. You supply the
memory, which means no hidden allocation.

The tradeoff is that **nothing is written until you `flush`**. Delete the
`try out.flush()` line above, press Run, and you will get no output at all. Try
it: click **Edit**, remove the line, and Run again.

<aside>

**A note on `std.debug.print`**: it writes to stderr, is unbuffered, and needs
no `Io`. That makes it convenient for quick debugging, but it is deliberately
not the tool for program output.

</aside>
