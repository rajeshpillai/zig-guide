A Zig ORM can derive its INSERT and UPDATE statements from the schema
struct at compile time, and build the matching values as an array of
tagged-union `Value`s from the same walk over the fields. The statement
and its values then cannot disagree in length or order.

## The problem

Reading was the [query builder](/learn/orm/query-builder/); writing is the
other half. An INSERT must name every column and number every placeholder; an
UPDATE must split key columns from data columns. Writing those statements by
hand, per table, is repetitive and easily goes out of date. The schema already
has the information to generate them.

## The pattern

1. Derive `insert_sql` at compile time, walking the column list and the
   placeholder list from the same fields.
2. Derive `update_sql` with a stated convention: the first field is the
   key. A convention that a library documents is part of its API, so choose
   it with care.
3. Pair each statement with `bind`, which turns a row into an array of
   tagged-union `Value`s, one per placeholder, in the same field order.

## The statement and its values cannot drift

`insert_sql`'s placeholders and `bind`'s output are generated from one walk
over one list of fields. Add a column to the struct and both change together
at the next compile. A common ORM bug is a statement
with four placeholders fed five values. Here that bug cannot be written,
because both come from one list.

`comptimePrint` does the number formatting during compilation, so even `$3` is
stored in the constant. At runtime, `bind` is a fixed sequence of stores; the
`inline for` leaves no loop behind.

## The Value union is the wire contract

Drivers do not take Zig structs; they take a statement and a list of typed
values. The value union is that list's element type. The compile error in the
mapping arm checks the schema's types against the driver's types. A field type
with no wire mapping fails the build, and the error names the field.

## In a full ORM

The draft goes further. It adds returning clauses to inserts, skips
auto-managed columns whose values come from the library rather than the
caller, and marks the key column explicitly instead of by position. All three
work by walking the same field list at compile time.
