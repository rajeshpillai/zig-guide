That is the whole game: three lanes, blocks coming at you, coins to collect. It
speeds up until you lose. A run lasts about half a minute.

## What is actually being taught

The game is the excuse. The subject is how to write one you can test.

Games resist testing for a reason that sounds like an excuse and is not. The
interesting behaviour is a loop that reads a keyboard, talks to a GPU and runs
sixty times a second, and none of those three things belongs in a test. So the
usual outcome is a game with no tests at all, tuned by playing it, where nobody
can say whether the difficulty curve is fair because nobody can state what fair
would mean.

This one has fifty-five tests. None of them opens a window.

## The decision that makes it possible

One module holds the rules of the game, and it imports nothing. No raylib, no
window, no clock, no allocator. It is a function from a seed and a list of
inputs to a list of states.

<GameSource file="src/sim/sim.zig" decl="Input" />

Everything else is downstream of that. The renderer reads the world and draws
it. The audio reads what happened and plays a note. Neither can change the
outcome of a run, which is why sound could be added to a finished game without
touching a rule.

This is the same shape the [networking chapters](/learn/networking/) use, where
protocol code parses from a `Reader` rather than a socket. A rule you can only
exercise by running the whole program is a rule you will not exercise.

## What that buys

The tests that follow are only possible because of it, and they are not the
tests you would expect from a game.

A program plays the course and asserts it never crashes, at every seed, for four
minutes of simulated time. That is the proof that the level generator is fair,
and it found a real bug: the policy steered into blocks whose centres had passed
the player but whose bodies still overlapped.

The same policy runs again with a delay in front of it, modelling a person's
reaction time, and the test asserts the mean run length lands in a band. A
perfect machine surviving a course says nothing about whether a person can play
it. This is the test that caught a difficulty curve which flattened out at sixty
seconds, so a sharp player simply never lost.

Two worlds run from one seed and one script of inputs, and are asserted to agree
on every tick.

## The shape of the project

```
src/
  sim/        the rules. imports nothing.
  render/     what it looks like. reads the world, never writes it.
  audio/      what it sounds like. holds no raylib either.
  platform/   raylib input and the audio device
  main.zig    window and the fixed timestep loop
```

The source is in the repository under `examples/lane-dodger/`. Every code block
in these chapters that carries a file path above it is read out of that file
when this page is built, so a chapter cannot describe a function that has been
deleted. The few blocks without a path are illustrations of what the code
deliberately does not do.

## What the chapters cover

[Vendoring raylib](/learn/lane-dodger/the-build/) and why the dependency is its

possible instead of tuned until it feels right. And
[sound](/learn/lane-dodger/sound/), which is a few hundred lines of arithmetic
and no audio files.
