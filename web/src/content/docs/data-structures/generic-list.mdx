The list in the previous chapter holds only `i32`. To make the list hold any type, you do not need a new language feature. Zig already has functions, and types are values at compile time.

```zig
fn List(comptime T: type) type {
    return struct {
        head: ?*Node = null,
        // ...
        const Self = @This();
        pub const Node = struct {
            value: T,
            next: ?*Node = null,
        };
    };
}
```

`List` is an ordinary function. Its argument is a type, and its return value is a type. The word `comptime` on the parameter tells that the argument must be known when the call occurs. You do not learn a separate generics system. This is the mechanism that [comptime](/learn/language-basics/comptime/) describes, applied to a struct definition.

## `@This()` and the reason for the name `Self`

Inside a type function, the struct is anonymous. Thus the struct has no name that you can use. `@This()` returns the struct, and `const Self = @This()` gives it a local name. Almost all Zig containers have this line, because they must have it.

## The result of the call is memoized

```
List(i32) == List(i32) -> true
List(i32) == List(u8)  -> false
```

When you call a type function two times with the same argument, the two calls return *the same type*. They do not return two types with the same structure. Without this rule, you could not give a `List(i32)` from a different part of the program to `fn takes(list: List(i32))`, because the two would be different types. This rule lets you use type functions in signatures.

## Each instantiation is a real struct

```
@typeName(List(u8).Node)    = generic-list.List(u8).Node
@typeName(List(Point).Node) = generic-list.List(generic-list.Point).Node
List(u8).Node == List(i32).Node -> false
```

The compiler instantiates the nested `Node` together with its list. Thus each `List(T)` gets its own node type, with a layout for its own `T`. The values are not boxed, the compiler erases no type information, and no shared code path takes a size parameter. This is monomorphization. A C++ template or a Rust generic does the same thing. Zig does it without a second syntax and without a separate compilation phase.

Because `Node` is nested, `List(i32).Node` and `List(u8).Node` are unrelated types. Thus you cannot give a node from one list to the other list. This rule comes from the structure. Nobody had to write it as a rule.

## Where equality comes from

`contains` must compare two `T` values, but `T` is not known when you write the code. `std.meta.eql` compares field by field. It works for integers, enums, and structs of those types. This covers the two examples in the snippet.

Be careful with one case: `std.meta.eql` compares slices by pointer and length, not by content. Two `[]const u8` slices can hold the same characters at different addresses. For these two slices, `std.meta.eql` returns false. A container that compares strings must get a comparison from you. This is the reason that `StringHashMap` is separate from `AutoHashMap`, and not a special case inside `AutoHashMap`.

The general answer is to take the comparison as a parameter. [Sorting](/learn/standard-library/sorting/) does the same with a `lessThan` function. A container that always uses `std.meta.eql` works until it gets the first type for which `std.meta.eql` is wrong.

## The standard library uses the same mechanism

```zig
var array: std.ArrayList(i32) = .empty;
defer array.deinit(allocator);
try array.append(allocator, 3);
```

[ArrayList](/learn/standard-library/arraylist/) uses the same idea, with contiguous storage instead of nodes. `std.ArrayList(i32)` is a call to a type function, exactly like `List(i32)`. When this call no longer looks like special syntax, the source of `std` becomes easier to read.

Copy one difference: on master, `ArrayList` does not store the allocator. Each method that can allocate takes an allocator as an argument. The list in this chapter stores the allocator. This is more convenient, but it costs one pointer in each instance. Also, two lists can then never share the bookkeeping of one arena. The standard library moved in the direction of the unmanaged form.
