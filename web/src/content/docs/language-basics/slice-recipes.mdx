A slice is a pointer and a length. Thus each recipe on this page writes to memory that already exists. No allocator is on this page.

## In place means that the length does not change

`std.mem.reverse` and `std.mem.rotate` write to the same bytes and return nothing. The two functions work on each `[]T`.

When you reverse a `[]const u8`, the function reverses the bytes, not the characters. Outside ASCII, this breaks each sequence of more than one byte, and the result is invalid UTF-8. [Unicode Recipes](/learn/standard-library/unicode-recipes/) is about this problem and others.

## Copies that overlap

`@memcpy` requires that the source and the destination do not overlap. A shift of elements inside one slice always overlaps. A release build does not tell you about the error. The check is a safety check, so it is not in the build where the bug costs the most.

`@memmove` handles the overlap. It works in the two directions. Before `@memmove`, there was the pair `std.mem.copyForwards` and `std.mem.copyBackwards`. With `@memmove`, you do not have to select a direction, and you cannot select the wrong direction. The two older functions are now deprecated, and the builtin replaces them.

Use `@memcpy` when you know that the ranges do not overlap. Use `@memmove` when the ranges possibly overlap.

## Remove an element

To remove an element, do these steps:

1. Move the tail one position lower, over the gap.
2. Make the slice one element shorter.

The backing array always keeps its length. Only the slice becomes shorter. `orderedRemove` does these steps for you on an `ArrayList`. Here they are without the container.

## Stop at a value

`std.mem.sliceTo` takes the part of a buffer before the first occurrence of a value. Use it when a different part of the program filled a fixed buffer and terminated its own output. Most C interop is of this type.

## Min, max, and all equal

`std.mem.findMin` and `findMax` return **indices**, not values. This looks strange at first. It is correct when a second array holds labels in the same order as the first array. The functions are for this case. `std.mem.allEqual` checks if all elements of the slice are equal, and you do not need a loop.

## An index belongs to its slice

An offset from one slice has no meaning in a different slice. `std.mem.find` on a sub-slice returns a position relative to that sub-slice. If you use the position on the parent, you have a bug. The type system cannot see this bug, because the two slices are `[]const u8`.

To convert the position, add the offset of the sub-slice. Alternatively, search the parent and then make the result narrower. When you use sub-slices, this mistake is easy to make with each function in the `find` family.

[Sorting](/learn/standard-library/sorting/) shows how to search a *sorted* slice, and how to sort a slice.
