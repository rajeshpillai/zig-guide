## The continue expression

```zig
while (i <= 10) : (i += 1) { ... }
```

The `: (i += 1)` part runs after **every** iteration — including ones cut short
by `continue`. That is precisely why it exists rather than just putting the
increment at the end of the body: with `continue` in the mix, the two are not
equivalent, and the bug that results is easy to miss.

## Loops that produce values

`break` can carry a value, and `while` can have an `else` branch that runs when
the loop finishes without breaking:

```zig
const found = while (i < 10) : (i += 1) {
    if (i * i > 20) break i;
} else 0;
```

This is the search-with-fallback pattern as a single expression, with no
sentinel variable and no way to forget the not-found case.
