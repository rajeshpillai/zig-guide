Compatibility with C raylib — what is verified, and how

Status as of 2026-10-16 (tag raylib-6.2-parity and later). This records how compatible the Zig port is with upstream C raylib, the evidence behind each claim, and — just as important — what is not covered.

Short answer: for the pinned configuration (raylib 6.2, Linux x86-64, desktop GLFW, OpenGL 3.3, default config.h), the Zig library is a drop-in replacement for C raylib: unmodified raylib programs compile against the same raylib.h, link against the Zig library, and render byte-identical frames for every upstream example that can be run deterministically (217 of 217), with numeric, audio and data functions bit-exact on their test grids. Outside that configuration, compatibility is not claimed.

3. Behavioral compatibility (does it do the same thing?)

The oracle is the same build of upstream C raylib (all-C library from the vendored 6.2 sources), compiled side by side; every gate compares C output to Zig output byte-for-byte — no tolerances.

Gate What is compared Result
zig build test 12 scenes (2D, text, textures, image ops, 3D shapes/meshes) rendered headless under mesa llvmpipe 12/12 framebuffers identical
tools/exdiff.sh (examples) every upstream example (unmodified), final frame after 240 frames, deterministic shim (fixed clock, hidden window, fixed RNG seed) 217/217 automated identical; 10 excluded (§4) = all 227 accounted for
zig build mathtest 148 raymath functions over a pseudo-random grid incl. edge cases (opposite vectors, TRS round-trips, cubic Hermite) 93,000 values bit-identical
zig build camtest / gesttest rcamera functions over an input grid / rgestures over scripted touch events 7,500 / 3,200 values bit-identical
zig build audiocheck decoded PCM (WAV/OGG/MP3/QOA/XM/MOD), Wave ops, export round-trips, stream/music metadata 43/43 identical
zig build datacheck compression, base64, file/data helpers 0 failures
zig build cdiff paths examples can’t reach, 12 programs: Text* and font loading (TTF/BMFont/image fonts, crafted .fnt files, ExportFontAsCode), hashes for lengths 0..200, path predicates, file system I/O on a real file tree, the automation events file (glibc fgets/sscanf edge cases), image ops across all 13 formats plus export/load, every model format and animation plus ExportMesh/AsCode and GenMesh*, wave export/format/crop, rlgl batches/shaders/readback, rshapes point lists and a 720-frame thickness/angle sweep; every TraceLog line compared 12/12 programs identical (Debug and ReleaseFast)
Real GPU spot check (EXDIFF_GPU=1) examples on Intel Iris Xe (Mesa 25.2.8, GL 4.6) instead of llvmpipe 219/219 identical (run before the last two audio exclusions)

Upstream behavior is reproduced including its quirks: e.g. ImageDrawTextPro is an empty stub in 6.2 and is a no-op here too; upstream example bugs are kept where they affect output.

4. What the oracle cannot see

These are limits of the evidence, not known incompatibilities:

  • Self-nondeterministic examples (10 excluded). Their C build disagrees with itself run-to-run, so no comparison is meaningful: 6 audio examples whose pixels follow the real-time audio thread (audio_mixed_processor, audio_module_playing, audio_raw_stream, audio_spectrum_visualizer, audio_stream_callback, audio_stream_effects), core_custom_frame_control (busy-waits on wall time), core_input_gestures_testbed, core_window_should_close (needs a key press), and rlgl_standalone (never calls the library). Reasons per example: test/examples.list.
  • One frame per example. The gate compares the final frame after 240 frames, not every frame (intermediate state that is later overdrawn is not compared).
  • No live input. Examples run without mouse/keyboard/gamepad input, so input-driven branches are covered only where cdiff, camtest and gesttest script them. Two real gaps were found this way (rtext’s SDF glyph generation; rshapes parameter ranges) — both fixed and now gated.
  • Audio playback. Decoding is byte-checked; what reaches the speaker in real time (mixing, device callbacks) is not.
  • GPU output in general. The gate runs on llvmpipe; one real GPU was spot-checked (identical). Other drivers are not verified, and GPU output is not guaranteed bit-deterministic.
  • Floating point. Byte-exactness is against C raylib compiled with -ffp-contract=off. C raylib built by clang with its default FMA contraction differs (in the last bit, sometimes in pixels) from this port — and from GCC builds of C raylib — on rotated/scaled geometry.
  • libm. A program linked by Zig takes sinf/cosf/… from Zig’s compiler_rt (one archive member that carries weak libm functions and replaces glibc’s once anything pulls it in, which Zig code always does). The gates pin both sides to it (pinCompilerRtMath in build.zig, -Wl,-u,__multi3 in tools/exdiff.sh). C raylib linked against glibc’s libm can differ in the last bit of trigonometric results (found in glTF animation poses).
  • Undefined behavior in C. Where upstream C has UB (e.g. out-of-range float→int casts, misaligned reads in bundled parsers), the Zig port picks the result C gives on x86-64 and is gated against it; it does not trap.

5. Known incompatibilities

Area Detail
Non-default config.h The Zig modules implement raylib’s default feature set. Code behind default-off flags is not ported: image formats TGA, JPG, PSD, HDR, PIC, PNM, KTX, ASTC, PKM, PVR, PEP; font format BDF; audio format FLAC; rshapes’ triangles fallback (SUPPORT_QUADS_DRAW_MODE=0). Rebuilding with different SUPPORT_* values changes the C oracle but not the Zig port.
Other platforms / GL versions Not compiled (see §1, not-migrated.md).
Shared library Only a static archive is built.
File system misuse Where C raylib’s result depends on undefined behaviour or on the filesystem, the Zig port picks one documented answer: LoadFileText on a directory returns NULL (“Failed to read text file”); C’s answer varies by filesystem (on ext4 it returns “”). LoadFileData/GetFileLength on a directory match C on ext4. ExportDataAsCode with dataSize <= 0 returns false (C reads data[-1]). NULL paths return NULL/false/0 where C would crash, and SaveFileText(f, NULL) writes an empty file (glibc writes “(null)”). A failed write makes SaveFileData/SaveFileText return false. LoadDirectoryFilesEx with no matches returns paths == NULL (C returns a calloc(0) pointer); count is 0 either way and UnloadDirectoryFiles accepts both.
Multi-page BMFont raylib 6.2 unloads atlas pages 1..n before drawing them into the merged atlas (rtext.c lines 2714/2727: a use-after-free, so its pixels are undefined). The port draws the pages, then unloads them. Page metadata is gated; the merged pixels can’t be.
Other misuse and allocation failure Where C crashes or reads out of bounds the port returns raylib’s failure result instead: a NULL file type in LoadWaveFromMemory, ExportImageAsCode/ExportWaveAsCode on empty data, NULL text arguments to Text* functions, malformed IQM/glTF offsets (read as zeros), negative GenImage* sizes, a failed allocation (logs a warning; raylib has no wording for it). rlGetShaderLocsDefault() after rlglClose returns NULL (C returns freed memory). LoadImageColors on a compressed format returns zeroed memory (C: uninitialized).

There are no known behavioral differences for valid inputs within the configuration of §1.

6. The idiomatic Zig API (a separate surface)

@import("raylib") is not ABI-compatible by design — it is a Zig API over the C ABI above, with raylib’s names and design (docs/zig-api.md). Its compatibility is checked differently:

  • Same behavior: every wrapper forwards to the gated C-ABI export, and 217 / 217 Zig-API translations of upstream examples render byte-identical to the original C examples (zig build apiexamples); 226 of 227 examples are translated (9 build-only for the §4 reasons; rlgl_standalone n/a).
  • Same layout: all API structs match translate-c’d raylib.h / rlgl.h (zig build apitest).
  • Deliberate differences from C raylib’s surface: loaders return error unions (a failed try rl.loadTexture returns an error where C returns an invalid texture); textFormat/traceLog use std.fmt syntax and rounding (signed zero-padding prints +6 where printf prints 06; exact ties round differently); setShaderValue infers the uniform type; enums/flags/slices replace ints and pointer+count pairs; raygui control results stay i32.

Re-verifying

zig build && zig build test mathtest camtest gesttest datacheck audiocheck cdiff apitest
python3 tools/constaudit.py
tools/exdiff.sh "$(find ~/.cache/zig-local -name libraylib_oracle.a | head -1)" zig-out/lib/libraylib.a
zig build apiexamples

Run the examples sweeps on a quiet machine: the audio-driven examples are timing-sensitive under heavy CPU load.
