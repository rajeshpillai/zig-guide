Vendor raylib

Updated 20 Oct 2026 · Code verified against Zig 0.18.0-dev.753+1420479be

raylib is a C library for windows, drawing and sound. This chapter connects raylib to a Zig project.

The one line version, and why it fails

raylib has a build.zig. With that file, the dependency should be one line:

const raylib = b.dependency("raylib", .{ .target = target, .optimize = optimize });

On Zig master today, that line itself does not compile. The failure occurs before the build compiles any of the C of raylib.

raylib/build.zig:95:10: error: member function expected 1 argument(s), found 2
raylib/build.zig:762:23: error: no field named 'build_root' in struct 'Build'

When you name a package in build.zig.zon, the build runner imports the build.zig of that package. The build compiles the build script of each dependency before it compiles any of your code. Thus, if the build script of a dependency does not support Zig master yet, your build fails before it gets to your code.

Both errors are in the Wayland detection of raylib, and this project does not use Wayland. That fact does not help. The full build script must type-check before the build gets to your code.

raylib-zig, the usual binding, is more out of date. It pins raylib 5.5, and it calls three standard library functions that do not exist on master now.

Neither project does something wrong. Both projects track releases. This guide tracks master. The breakage comes from that difference. Thus it is better to know about the breakage before you add the dependency.

Depend on the C instead

The C of raylib changes much more slowly than the build API of Zig. Thus this project depends on the C.

1. Fetch the source

Clone raylib at a pinned commit into a directory that the build can read. Pin the commit, because a dependency without a pin can change without your knowledge.

git init vendor/raylib
git -C vendor/raylib remote add origin https://github.com/raysan5/raylib.git
git -C vendor/raylib fetch --depth 1 origin <commit>
git -C vendor/raylib checkout FETCH_HEAD

Keep src/ and the licence. Delete all other files. The examples/ directory of raylib is 72 MB by itself, and the build compiles none of it. In this project, fetch-raylib.sh does these steps and records the commit that it fetched.

Add vendor/ to .gitignore. The script is the record. The vendored copy is not the record.

2. Do not declare it in build.zig.zon

vendor/raylib stays a plain directory of C files. The build runner imports the build script of each declared package, and it never looks at a plain directory. Thus nothing reads the build.zig of raylib.

3. Compile the C

const mod = b.createModule(.{
    .target = target,
    .optimize = optimize,
    .link_libc = true,
});
const lib = b.addLibrary(.{ .name = "raylib", .linkage = .static, .root_module = mod });

mod.addCMacro("PLATFORM_DESKTOP_GLFW", "");
mod.addCMacro("GRAPHICS_API_OPENGL_33", "");
mod.addCMacro("_GLFW_X11", "");

mod.addIncludePath(b.path("vendor/raylib/src/platforms"));
mod.addIncludePath(b.path("vendor/raylib/src/external/glfw/include"));
mod.addCSourceFiles(.{
    .root = b.path("vendor/raylib/src"),
    .files = &.{ "rcore.c", "rshapes.c", "rtextures.c", "rtext.c", "raudio.c", "rglfw.c" },
    .flags = &.{"-std=gnu99"},
});

for ([_][]const u8{ "GL", "X11", "Xrandr", "Xinerama", "Xi", "Xcursor" }) |name| {
    mod.linkSystemLibrary(name, .{});
}

The build compiles six C files. rglfw.c is the copy of GLFW that raylib includes, and GLFW is the layer that makes the windows. The other files are the modules of raylib. The SUPPORT_MODULE_* macros turn these modules on and off.

On Debian or Ubuntu, these packages supply the system libraries:

sudo apt-get install libx11-dev libxrandr-dev libxinerama-dev \
                     libxi-dev libxcursor-dev libgl1-mesa-dev

You do not need an ALSA package. The audio backend of raylib loads libasound at runtime, and does not include its header. Thus the game compiles without libasound, and it is silent when no device exists.

4. Change raylib.h into a Zig module

The language does not have @cImport now. C headers now come through a build step.

const translated = b.addTranslateC(.{
    .root_source_file = b.path("vendor/raylib/src/raylib.h"),
    .target = target,
    .optimize = optimize,
    .link_libc = true,
});
const rl = translated.createModule();
rl.linkLibrary(lib);

exe_mod.addImport("rl", rl);

5. Use it

const rl = @import("rl");

pub fn main() void {
    rl.InitWindow(540, 960, "Lane Dodger");
    defer rl.CloseWindow();

    while (!rl.WindowShouldClose()) {
        rl.BeginDrawing();
        rl.ClearBackground(rl.RAYWHITE);
        rl.DrawText("hello", 20, 20, 24, rl.BLACK);
        rl.EndDrawing();
    }
}

translate-c does not change the names. Thus the documentation of raylib applies directly.

The full function

The macros are a copy of the macros in the build script of raylib. That is the cost of this method. When raylib changes its configuration, this function must change too. The list of macros is a dozen lines. A mismatch fails at compile time. A mismatch does not silently make a different library.

The same source, on a canvas

The platform choice has an effect in two places: the raylib module above, and a separate addWeb step that runs emcc.

The desktop build uses PLATFORM_DESKTOP_GLFW with OpenGL 3.3 and the copy of GLFW that raylib includes. The web build uses PLATFORM_WEB with GLES 3, and it does not compile rglfw.c. Emscripten supplies its own GLFW, which it connects to the canvas.

Zig compiles the game and raylib to a static library for wasm32-emscripten. emcc does the link. Emscripten supplies the JavaScript glue, the GL context and the canvas configuration.

Two flags in that function prevent silent failures.

-sMIN_WEBGL_VERSION=2. GLES 3 emits #version 300 es shaders, and these shaders need a WebGL 2 context. Emscripten creates a WebGL 1 context unless you tell it to do otherwise. The symptom is a game that loads, runs, reports no error, and compiles no shader.

.sanitize_c = .off on the raylib module. In the debug modes, Zig instruments C with UBSan and links its own runtime to catch the reports. That runtime comes with a Zig link. Here emcc does the link. Thus the instrumentation leaves dozens of undefined __ubsan_* symbols.

Run it

cd examples/lane-dodger
./fetch-raylib.sh
zig build run -Doptimize=ReleaseFast

The browser build is a .wasm file of 200 KB, and approximately the same quantity of JavaScript. The browser build needs the Emscripten SDK:

zig build web -Doptimize=ReleaseFast
python3 -m http.server -d zig-out/web 8080
