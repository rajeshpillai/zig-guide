Build It From Scratch

Updated 20 Oct 2026 · Code verified against Zig 0.18.0-dev.753+1420479be

The other chapters explain what each part does. This chapter gives the order in which to write the parts.

You can stop and check your work at two points. The first point comes before you draw anything, and it runs the full game.

What you need

You need Zig master, and not 0.16. The game uses std.process.Init, std.Io.Dir, std.mem.printSentinel and @splat on arrays. All of these came after 0.16. build.zig.zon gives the exact minimum version.

zig version    # 0.17.0-dev.1676 or newer

You also need Git and a C compiler. On Debian or Ubuntu, the game also needs the X development headers:

sudo apt-get install libx11-dev libxrandr-dev libxinerama-dev \
                     libxi-dev libxcursor-dev libgl1-mesa-dev

You do not need an ALSA package. The audio backend of raylib loads libasound at runtime, and does not include its header.

Part one: the project structure

1. Make the directory tree.

mkdir -p lane-dodger/src/{sim,render,audio,platform,tools}
cd lane-dodger

2. Tell Git to ignore the raylib copy. Add one line to .gitignore:

vendor/

The fetch script below records which raylib commit the game uses. The copy that the script downloads is 13 MB, thus the copy stays out of Git.

3. Write the package file.

zig build does not accept the fingerprint, and prints the correct value. Paste that value into the file.

raylib is not in .dependencies. This is intentional, and Vendor raylib gives the reason.

4. Write the fetch script.

chmod +x fetch-raylib.sh && ./fetch-raylib.sh

5. Write the build script.

Nothing compiles yet. build.zig names files that do not exist, and that is correct. Zig reads a source file only when a step that needs the file runs.

Part two: the simulation

Write these nine files in this order. Each file uses only the files above it.

  • src/sim/config.zigEvery tunable number, and the field geometry. The World.
  • src/sim/rng.zigPCG32, so a seed replays exactly. The World.
  • src/sim/pool.zigFixed-capacity storage with generational handles. Handles, Not Pointers.
  • src/sim/sim.zigThe world, the tick, collision and spawning. The World.
  • src/sim/bot.zigA policy that plays the game. Difficulty You Can Prove.
  • src/sim/tests.zigThe tests that play the game. Difficulty You Can Prove.
  • src/render/palette.zigColours as plain data, no raylib. Draw It.
  • src/render/particles.zigSparks and debris, using the same pool. Draw It.
  • src/audio/synth.zigFive sound effects, generated. Sound Without Sound Files.

The first checkpoint

zig build test

The command runs fifty-five tests:

  • A bot plays four minutes of the game at each seed.
  • A second bot plays the game with a human reaction time.
  • Two worlds replay from one seed, and the test compares them on each tick.

You did not write drawing code, input code or main.zig yet. You do not need a window or an audio device. But the game is already sufficiently complete to play and to check. The design has this arrangement so that this checkpoint exists.

If the tests pass, the rules are correct. The other files draw the game, read the input and play the sound.

Part three: the game you can see

Write four more files.

  • src/render/draw.zigThe view transform and every raylib call. Draw It.
  • src/platform/input.zigKeys and taps, read one time in each frame. Input.
  • src/platform/audio.zigThe audio device, and the sounds on it. Sound Without Sound Files.
  • src/main.zigThe window and the fixed timestep loop. The Loop Takes No dt.
zig build run -Doptimize=ReleaseFast

To change lane, use A and D or the arrow keys. Space starts a run. M stops the sound.

Optional

One more file writes the sound effects to .wav files. Then you can listen to each effect, and you do not have to play the game until the effect occurs.

  • src/tools/dump_sounds.zigRenders the five clips to a directory. Sound Without Sound Files.
zig build sounds && ls zig-out/sounds

How one tap becomes a frame

you press D
   |
   v
Latch.poll()            once per rendered frame, sets latch.right
   |
   v
Game.frame()            adds real elapsed time to the accumulator
   |
   v
while accumulator >= 1/120:
     Input = latch.take()      first tick gets the press, the rest get nothing
     World.step(input)         steer, move, spawn, collide, score
     react(events)             particles, screen shake, a note
   |
   v
alpha = accumulator / (1/120)      what is left over, less than one tick
   |
   v
draw.frame(world, alpha)    draws between the last two ticks

The press gets to exactly one tick. If a frame needs no ticks, the frame keeps the press for the next frame. If a frame needs three ticks, the frame gives the press to the first tick.

If the build fails

error: invalid fingerprint. This error is normal on the first run. Paste the value that the compiler prints into build.zig.zon.

error: unable to find module 'rl', or the compiler cannot find the raylib headers. fetch-raylib.sh did not run, or it ran in the wrong directory. Make sure that vendor/raylib/src/raylib.h exists.

ld: cannot find -lX11 and similar errors. The X development headers are not on your system. Install the packages in the list above. The runtime libraries alone are not sufficient. You need the -dev packages.

root source file struct 'std' has no member named .... Your Zig is too old, or too new. This game tracks master, thus both of these problems can occur. Compare zig version with minimum_zig_version.

The tests pass but the window is black. You use Wayland without XWayland, or a container with no display. To make sure that the program itself runs, try xvfb-run -a ./zig-out/bin/lane-dodger.

The game builds, but it plays badly. All the numbers are in src/sim/config.zig. Change lane_change_time first. Do not make the row spacing smaller by hand. sim.zig calculates a minimum from the other numbers, and the tests tell you when the spacing is less than that minimum.
